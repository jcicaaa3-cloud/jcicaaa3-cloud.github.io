暗号化したファイルを送るたびにパスワードを別に伝えるのが面倒だったので、RSAの公開鍵とAESの鍵を組み合わせる方式でツールを作っています。Windows PowerShellとC#で構成していて、ここには構成とテストする項目を書きました。実際のログや秘密鍵、パスワードは載せていません。

## 構成

ファイルの本文はAESで暗号化し、そのファイルだけに使ったAESの鍵を受信者のRSA公開鍵で暗号化します。こうすればRSAで大きなファイルを直接扱う必要がありません。

```text
送るファイル ── AES暗号化 ──────────── 暗号文
                  │
             ランダムなAES鍵
                  │
          受信者のRSA公開鍵
                  │
            暗号化された鍵

受信者：RSA秘密鍵でAES鍵を復元 → ファイルを復号
```

アルゴリズムはAES-256-GCMとRSA-OAEP（SHA-256）を基準にしました。GCMの認証タグの検証に失敗したら、復号結果は捨てる必要があります。

## 実装で確認すること

| 項目 | 確認する内容 |
| --- | --- |
| AES鍵 | ファイルまたは作業ごとに新しく作るか |
| GCM nonce | 同じ鍵で再利用していないか |
| RSA | OAEPの設定が送信側と受信側で同じか |
| 改ざん検知 | ヘッダー、暗号文、タグが変わったら拒否するか |
| ファイル処理 | 大きなファイルやフォルダをメモリを使いすぎずに処理できるか |
| 復号ツール | 受信者のPCで同じ形式を読めるか |

暗号化の途中でエラーが起きたりタグが合わなかったりしたときに、不完全な平文が残らないようにする必要があります。ファイルサイズ、作業の中断、間違った秘密鍵といったケースもテスト項目に入れました。

## ZIPではないということ

`.cpenc`や`.cprsa`のような独自形式にすると、7-Zipで開ける普通のZIPファイルとは別物になります。受信者にも同じ形式を読めるツールが必要なので、暗号化ができるかと、受信側のPCで復号できるかは別々に確認する必要があります。

## まだやっていないテスト

- 小さいファイル・大きいファイルの暗号化と復号の往復
- 暗号文の一部を変えたときのエラー処理
- 間違った秘密鍵とパスワードの入力
- 中断した作業の一時ファイルの後始末
- 別のWindows環境で再現できるか

テストを回したら、入力条件とエラーメッセージも一緒に載せます。
