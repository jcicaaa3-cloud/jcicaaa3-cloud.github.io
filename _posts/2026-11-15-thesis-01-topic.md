## 1. 로봇 평가 연구에서 악성코드로 {#from-robot}

1학기에는 로봇 행동 평가를 연구했습니다. OpenVLA-OFT를 LIBERO-Spatial 환경에서 80회 돌리고, 잡기·놓기 같은 이벤트 874개를 성공과 실패로 판정하는 기준을 비교했습니다. 판정 기준과 정답 레이블을 바꾸자 같은 기록에서 F1이 0.9111에서 0.5970으로 내려갔습니다. 모델은 그대로인데 평가 방식만 바꿔도 숫자가 이만큼 움직였습니다.

이 연구를 마무리하면서 평가와 검증을 다루는 역량을 키웠고, 졸업논문은 중학생 때부터 관심을 두어 온 악성코드 분야로 이어 가기로 했습니다. 랜섬웨어 탐지 논문을 읽으면서도 로봇 연구 때와 같은 점을 먼저 확인하고 싶었습니다. 탐지율 98%가 어떤 샘플로 시험해서 나온 숫자인지입니다.

## 2. 먼저 샘플을 열어 봤습니다 {#samples-first}

주제를 정하기 전에 실제 랜섬웨어를 몇 개 열어 봤습니다. 탐지 모델이 무엇을 놓치는지 말하려면 놓친 파일 안에 뭐가 들었는지 직접 볼 수 있어야 한다고 생각했습니다.

- **Calipso**: 11월 5일에 공개 보고서를 정리하고, 6일부터 Ghidra로 정적 분석했습니다. XChaCha20으로 파일 앞 5MB만 암호화하고, 로컬 NTFS 드라이브는 MFT를 직접 열거해서 파일을 찾는 구조였습니다. [분석 v2.0]({{ '/research/calipso-v2/' | relative_url }})에 정리했습니다.
- **HYFLOCK**: 11월 8일에 [다음 분석 대상]({{ '/research/hyflock-preview/' | relative_url }})으로 정하고, 11월 12일에 [해시와 엔진별 탐지 결과]({{ '/research/hyflock-01/' | relative_url }})를 적었습니다. VirusTotal 67개 엔진 중 28개가 탐지했는데, 랜섬웨어 이름을 붙인 엔진끼리도 Killav, Nishi, Qilin으로 이름이 갈렸습니다.

HYFLOCK 탐지명이 갈린 것은 나중에 논문 4장의 한계에 들어갔습니다. 탐지 데이터셋의 패밀리 레이블도 결국 이런 탐지명을 바탕으로 붙기 때문입니다. 같은 계열이 다른 이름으로 나뉘어 있으면 패밀리를 나눠서 평가해도 완전히 나뉘지 않습니다.

Calipso는 논문 선정 기준과 상관없이 먼저 본 샘플이라 최종 원고 본문에서는 뺐습니다.

## 3. MLRan과 공개 분할 {#mlran}

데이터는 MLRan을 골랐습니다. 2026년에 Journal of Network and Computer Applications에 실린 공개 행위 데이터셋이고, 코드와 데이터가 모두 공개되어 있어서 다시 돌려 볼 수 있습니다.

| 항목 | 내용 |
| --- | --- |
| 샘플 | 4,880개 (랜섬웨어 2,330, 정상 소프트웨어 2,550) |
| 랜섬웨어 패밀리 | 64개 (암호화형 32, 모던 15, RaaS 13, 로커 4), 패밀리당 5~134개, 중앙값 28 |
| 기간 | 2006~2024년 (랜섬웨어는 2008~2024년) |
| 실행 환경 | Cuckoo Sandbox 2.0.7, Windows 7 게스트, 샘플당 120초 |
| 특징 | 원시 6,467,926개 → 상호정보량 선별 24,162개 → RFE 483개, 모두 0/1 값 |
| 483개의 범주별 개수 | STR 223, REG 90, API 63, SYS 38, DROP 23, SIG 20, FILE 16, DIR 10, NET 0 |
| 원 연구의 분할 | 샘플 유형별 VirusTotal 최초 제출일 순 80:20, 학습 3,905 / 시험 975 |
| 원 연구 정확도 | LR 98.15% (5개 모델 중 최고), LightGBM 94.05% |

패밀리당 개수, 범주별 특징 수, 분할 크기는 공개 저장소의 메타데이터와 분할 파일을 제가 직접 센 값입니다. 정확도는 원 논문 arXiv 판의 표 6에서 가져왔습니다. 실험에는 GitHub 저장소 커밋 `273fcac`와 Zenodo 레코드 23403681의 파일을 고치지 않고 썼습니다.

원 연구의 분할 방식은 이렇습니다. 샘플을 유형별로 나누고, 각 유형 안에서 VirusTotal에 처음 올라온 날짜 순으로 줄을 세운 뒤 오래된 80%를 학습에, 최근 20%를 시험에 넣었습니다. 유형 안에서는 시간 순서가 지켜집니다. 그런데 유형마다 경계 날짜가 다를 수 있어서, 한 유형의 학습 샘플이 다른 유형의 시험 샘플보다 늦을 수는 있습니다.

원 논문은 패밀리 단위로 나눈 평가를 하지 않았고, 처음 보는 패밀리에 대한 일반화를 한계로 적어 두었습니다.

## 4. 분할 파일을 세어 보니 {#overlap}

공개된 분할 파일을 열고 시험 세트의 랜섬웨어가 어느 패밀리인지 셌습니다.

| | 개수 |
| --- | --- |
| 시험 세트 랜섬웨어 | 465 |
| 그중 같은 패밀리가 학습 세트에도 있는 샘플 | 451 (97.0%) |
| 시험 세트에만 있는 패밀리 | Akira 1개 (14개 샘플) |

시험 랜섬웨어 100개 중 97개는 학습 때 이미 본 패밀리의 다른 샘플이었습니다. 98%라는 탐지율은 대부분 "아는 패밀리의 새 샘플"을 맞힌 결과라는 뜻입니다. 학습에 없던 패밀리를 얼마나 잡는지는 이 분할로 알 수 없습니다.

실제로는 두 경우가 다 생깁니다. 이미 알려진 패밀리의 변종도 들어오고, 처음 보는 패밀리도 들어옵니다. 그래서 두 조건의 성능을 따로 봐야 한다고 생각했고, 이 숫자가 논문의 출발점이 되었습니다.

## 5. 이미 나와 있는 연구 {#prior}

평가 방식이 결과를 부풀린다는 지적은 이미 여러 번 나왔습니다.

- Pendlebury 등(TESSERACT, USENIX Security 2019)은 시간 순서를 지키지 않는 분할과 실제와 다른 클래스 비율이 악성코드 분류 성능을 부풀린다는 것을 보였습니다.
- Arp 등(USENIX Security 2022)은 보안 분야 머신러닝의 흔한 함정으로 데이터 스누핑, 표본 편향, 허위 상관을 들었습니다.
- Ju와 Kim(IEEE Access 2025)은 I/O 순서를 바꾼 랜섬웨어가 기존 행위 기반 탐지를 피할 수 있다는 것을 보였습니다.

조사하다가 MLRan을 패밀리 기준으로 다시 평가한 논문도 찾았습니다. Nti(Future Internet 2026)는 MLRan의 483개 특징으로 계층형 희소 신경망을 제안하면서 층화, 시간순, 패밀리 분리, 오픈셋 네 가지 분할을 비교했고, 비교 모델에 LR도 넣었습니다. 제가 하려던 것과 겹치는 부분이 있어서 차이를 정리했습니다.

- Nti의 패밀리 분리는 샘플이 10개 이상인 패밀리만 60:20:20으로 나눈 한 번의 분할입니다. 저는 64개 패밀리를 모두 넣은 5겹 교차검증을 했습니다.
- Nti는 세부 오류 분석과 신뢰구간·가설 검정을 하지 않았다고 밝혔습니다. 저는 놓친 샘플을 SHAP과 역공학으로 따라가고, 대응 비교에 검정을 붙였습니다.

그래서 논문 서론에 "MLRan에 패밀리 분리 평가를 적용한 것 자체는 본 논문이 처음이 아니다"라고 적었습니다. 새로운 점은 오류 분석과 통계 검정 쪽에 있습니다.

설명 쪽도 비슷했습니다. MLRan 원 논문은 SHAP과 LIME으로 주요 지표를 보여 주고 오분류 사례 몇 개에 LIME을 적용했지만, 맞힌 샘플과 놓친 샘플의 기여도를 집단으로 비교하지는 않았습니다. 새 탐지기를 만들기보다 기존 베이스라인이 어디서, 왜 틀리는지를 보는 쪽으로 방향을 잡았습니다.

## 6. 연구 질문과 가설 {#rq}

| | 질문 |
| --- | --- |
| RQ1 | MLRan 베이스라인 2개를 패밀리 분리 조건에서 평가하면 시간순 분할에 비해 랜섬웨어 재현율이 얼마나 달라지는가 |
| RQ2 | 패밀리 분리 조건에서 참양성(TP)과 거짓음성(FN) 사이에 SHAP 기여도는 특징 범주별로 어떻게 다른가 |
| RQ3 | 탐지 실패 사례를 정적 역공학으로 분석하면 특징 표현과 바이너리 기능 사이에서 무엇이 일치하고 무엇이 어긋나는가 |

가설은 두 개를 세웠습니다.

- **H1**: 패밀리를 분리하면 랜섬웨어 재현율이 시간순 분할보다 낮아지고, 그 하락이 일부 패밀리에 몰린다.
- **H2**: FN에서는 문자열(STR)과 레지스트리(REG) 범주의 부호 있는 기여도 합이 TP보다 랜섬웨어 쪽으로 덜 기울어 있다.

H2는 처음에 FILE·DIR 범주로 세웠다가 바꿨습니다. 483개 특징 중 FILE과 DIR은 합쳐 26개(5.4%)뿐이었고, STR과 REG가 313개(64.8%)였습니다. 처음 가설의 결과도 논문에 같이 적었습니다. 사전 등록한 가설이 아니어서 RQ2의 검정은 탐색적 분석으로 표시했습니다. 자세한 건 [2편]({{ '/research/thesis-02/' | relative_url }})에 있습니다.

베이스라인은 LR과 LightGBM 두 개로 정했습니다. LR은 원 연구에서 정확도가 가장 높았고, LightGBM은 다섯 모델 중 두 번째로 낮았지만 트리 모델이라 TreeSHAP으로 SHAP 값을 정확히 계산할 수 있습니다.

역공학할 실패 사례는 결과를 보기 전에 기준을 정해 두었습니다.

1. 패밀리 분리 조건에서 재현율이 가장 낮은 패밀리의 샘플
2. 정상일 확률이 가장 높게 나온 FN
3. 범주별 기여도 비율이 TP 평균과 가장 다른 FN
4. 2023~2024년 정상 소프트웨어에서 나온 FP 1건 (원 연구의 FP 12건 중 11건이 이 시기 샘플)

실제로는 이 기준을 일부만 적용할 수 있었습니다. 어떻게 됐는지는 [3편]({{ '/research/thesis-03/' | relative_url }})에 적었습니다.

## 7. 증거를 나눠 적는 규칙 {#evidence}

SHAP은 모델이 어떤 특징을 썼는지 알려 줄 뿐, 악성코드가 실제로 무엇을 했는지는 알려 주지 않습니다. 역공학으로 찾은 기능도 바이너리 안에 있다는 것까지만 확인되고, 120초 실행에서 그 기능이 쓰였는지는 알 수 없습니다. 그래서 논문의 모든 소견에 출처 표시를 붙였습니다.

| 구분 | 근거 | 보일 수 있는 것 | 보일 수 없는 것 |
| --- | --- | --- | --- |
| S (정적) | Ghidra, PE 구조, 바이트 확인 | 코드나 파일 구조에 그 기능이 있다는 것 | 그 기능이 실행된다는 것 |
| D (동적) | MLRan 특징 행렬, 출처를 밝힌 실행 기록 | 어느 1회의 실행에서 그 기록이 남았다는 것 | 모든 실행·환경에서 일어난다는 것, 특징으로 표현되지 않은 동작 |
| M (모델) | SHAP 기여도 | 분류기가 사용한 특징과 방향 | 악성코드가 실제로 한 동작. D와 독립된 근거가 되지 않음 |
| R (외부 보고) | 출처를 밝힌 제3자 보고서 | 보고서가 밝힌 해시 등재와 분석 결과 | 제 재확인, 보고서가 밝히지 않은 세부 |

소견마다 수준도 붙였습니다.

- **확인**: 바이트, 코드, 특징값처럼 직접 본 사실
- **해석**: 여러 관찰과 들어맞지만 직접 확인하지 않은 설명
- **가설**: 추가 확인이 필요한 설명

실패 원인에 관한 문장은 해석이나 가설 수준을 넘지 않게 했습니다.

이 표는 처음부터 이 모양은 아니었습니다. 초기 원고에는 "서로 다른 구분의 증거 두 개가 같은 방향이면 주장한다"는 규칙이 있었습니다. 그런데 M은 D에서 뽑은 특징 위에서 계산되니 둘이 같은 방향인 건 당연한 일에 가깝습니다. 이 문제를 고치면서 "M은 D와 독립된 근거가 아니다"를 표에 넣고, 증거 개수 대신 소견별 수준을 적는 방식으로 바꿨습니다. R도 나중에 따로 뺐습니다. Check Point 보고서의 동적 분석 결과를 처음에는 "D(제3자)"로 적었는데, 제가 재확인하지 않은 내용을 제 관찰과 같은 칸에 두는 게 맞지 않았습니다.

## 8. 전체 절차 {#procedure}

## 9. 분석 환경과 안전 규칙 {#safety}

탐지 실험은 MLRan이 공개한 특징 벡터 CSV만 씁니다. 악성코드 파일이 없으므로 평소 쓰는 PC에서 돌렸습니다. Windows 11, Python 3.12.10, scikit-learn 1.6.1, LightGBM 4.6.0이고 난수 시드는 `20261113`입니다.

샘플 실물은 VMware Workstation Pro의 Windows 11 가상 머신 안에서만 다뤘습니다.

- 네트워크 어댑터와 USB 컨트롤러를 지웠습니다.
- 공유 폴더, 클립보드 공유, 드래그 앤 드롭을 껐습니다.
- 샘플을 넣기 전 스냅샷을 남겼습니다.
- 분석 스크립트는 샘플의 SHA-256이 지정한 값과 같고, WAN Miniport를 뺀 활성 네트워크 어댑터와 기본 경로가 없을 때만 돌아가게 했습니다.
- 작업은 PE 구조 파싱, 문자열 추출, Ghidra 12.2 headless 분석, PowerShell 바이트 읽기뿐입니다. 논문에 나오는 두 샘플은 실행하지 않았습니다.
- 가상 머신 밖으로는 텍스트와 CSV 결과만 가져왔습니다. 샘플은 SHA-256으로만 가리킵니다.

11월 6일에 Calipso를 이 가상 머신에서 한 번 실행한 적이 있습니다([Calipso (3)]({{ '/research/calipso-03/' | relative_url }})). 그 관찰은 논문의 근거로 쓰지 않았고, 2.5절에 그 사실을 적어 두었습니다.

다음 글에서는 공개 분할 재현부터 패밀리 분리 평가, 특징 재선택, SHAP 분석까지의 실험을 적습니다.
