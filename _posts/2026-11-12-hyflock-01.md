## 메타데이터에서 본 것

- **TimeStamp가 0**입니다. 빌드 시각 정보가 비어 있어 컴파일 시점을 이 값으로는 알 수 없습니다.
- **LinkerVersion이 3**입니다. Go 툴체인으로 빌드한 Windows 바이너리에서 흔히 보이는 값과 같습니다. Check Point 보고서에서 설명한 Go Carrier 구조와 맞는지는 다음 편에서 pclntab 등을 직접 확인한 뒤에 판단하겠습니다.
- **파일 크기에 비해 CodeSize가 작습니다.** CodeSize는 726,528 bytes이고 전체 파일은 약 3.85MB입니다. 나머지 영역에 무엇이 들어 있는지는 섹션과 오버레이를 확인해야 알 수 있습니다.
- **디버그 정보가 없습니다.** `No debug`, `stripped to external PDB`로 표시됩니다.
- **TrID 결과는 일반 분류에 그칩니다.** 가장 높은 항목도 `Win64 Executable (generic)` 37.0%라서 계열을 판단하는 데는 쓰기 어렵습니다.

## 탐지 결과에서 본 것

- **계열 이름이 엔진마다 다릅니다.** Qilin(huorong), Nishi(Ikarus), Killav(Alibaba, Microsoft)처럼 서로 다른 계열명이 붙어 있습니다. 랜섬웨어라는 판단은 여러 엔진이 공유하지만, 어떤 계열인지에 대해서는 일치하지 않습니다.
- **Microsoft 탐지명에 `MSIL`이 들어 있습니다.** MSIL은 보통 .NET 바이너리에 붙는 표기입니다. 그런데 파일 형식 정보에는 .NET 관련 표시가 없습니다. CLR 헤더가 실제로 있는지 다음 편에서 확인하겠습니다.
- **랜섬웨어를 명시하지 않은 탐지가 18개입니다.** 28개 중 18개는 ML·평판 계열이거나 일반 악성 표기입니다. 악성이라는 판단과 랜섬웨어라는 분류가 엔진마다 따로 이루어진다는 점을 보여 줍니다.
- **39개 엔진은 탐지하지 않았습니다.** 이번 글에서는 미탐 원인을 추정하지 않습니다. 같은 계열의 다른 빌드와 탐지 결과를 비교한 뒤, 정적 특징과 연결해서 다루겠습니다.

## 아직 하지 않은 것

- PE 헤더, 섹션, 엔트로피, 임포트 확인
- Go Carrier와 내부 페이로드의 관계 확인
- 다른 HYFLOCK 빌드와의 탐지 결과 비교
- Check Point 보고서 내용과의 대조

다음 편에서는 파일을 직접 열어 PE 구조와 Go Carrier를 봅니다.
