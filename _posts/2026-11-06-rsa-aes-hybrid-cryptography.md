파일을 암호화해서 보낼 때마다 비밀번호를 따로 알려주는 게 번거로워서, RSA 공개키와 AES 키를 같이 쓰는 방식으로 도구를 만들고 있습니다. Windows PowerShell과 C#으로 구성했고, 여기에는 구조와 테스트할 항목을 적었습니다. 실제 로그나 개인키, 비밀번호는 올리지 않습니다.

## 구조

파일 본문은 AES로 암호화하고, 그 파일에만 쓴 AES 키를 수신자의 RSA 공개키로 암호화합니다. 이렇게 하면 RSA로 큰 파일을 직접 처리할 필요가 없습니다.

```text
전송할 파일 ── AES 암호화 ──────────── 암호문
                  │
              임의 AES 키
                  │
         수신자 RSA 공개키
                  │
             암호화된 키

수신자: RSA 개인키로 AES 키 복원 → 파일 복호화
```

알고리즘은 AES-256-GCM과 RSA-OAEP(SHA-256)를 기준으로 잡았습니다. GCM 인증 태그 검증에 실패하면 복호화 결과를 버려야 합니다.

## 구현할 때 확인할 것

| 항목 | 확인할 내용 |
| --- | --- |
| AES 키 | 파일 또는 작업마다 새로 만드는지 |
| GCM nonce | 같은 키로 재사용하지 않는지 |
| RSA | OAEP 설정이 보내는 쪽과 받는 쪽에서 같은지 |
| 변조 검사 | 헤더, 암호문, 태그가 바뀌면 거부하는지 |
| 파일 처리 | 큰 파일과 폴더를 메모리를 과하게 쓰지 않고 처리하는지 |
| 복호화 도구 | 받는 사람 PC에서 같은 형식을 읽을 수 있는지 |

암호화 도중 오류가 나거나 태그가 맞지 않을 때 불완전한 평문이 남지 않게 해야 합니다. 파일 크기, 작업 중단, 잘못된 개인키 같은 경우도 테스트 목록에 넣었습니다.

## ZIP이 아니라는 것

`.cpenc`, `.cprsa`처럼 자체 형식을 쓰면 7-Zip으로 여는 일반 ZIP 파일과는 다릅니다. 받는 사람도 같은 형식을 읽는 도구가 있어야 열 수 있어서, 암호화가 되는지와 받는 쪽 PC에서 복호화가 되는지는 따로 확인해야 합니다.

## 아직 안 해 본 테스트

- 작은 파일, 큰 파일 암호화·복호화 왕복
- 암호문 일부를 바꿨을 때 오류 처리
- 잘못된 개인키와 비밀번호 입력
- 중단된 작업의 임시 파일 정리
- 다른 Windows 환경에서 재현되는지

테스트를 돌리면 입력 조건과 오류 메시지까지 같이 올리겠습니다.
