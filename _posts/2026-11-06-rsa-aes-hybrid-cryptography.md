## 로그 파일을 보호하는 방법을 고민했다

파일이나 폴더를 암호화해서 다른 사람에게 전달할 때마다 같은 비밀번호를 공유하는 방식이 번거로웠다. 그래서 RSA 공개키와 AES 대칭키를 함께 쓰는 형태를 검토했다. Windows PowerShell과 C#으로 도구를 구성하면서 신경 쓴 부분도 기록해 둔다.

여기에는 암호화 구조와 테스트할 내용을 적었다. 실제 암호화 로그, 개인키, 비밀번호는 올리지 않았다.

## 데이터와 키를 따로 처리한다

파일 본문은 AES로 암호화한다. RSA로 큰 파일을 직접 처리하지 않고, 그 파일에만 사용한 AES 키를 수신자의 공개키로 암호화한다.

```text
전송할 파일 ── AES 암호화 ──────────── 암호문
                  │
              임의 AES 키
                  │
         수신자 RSA 공개키
                  │
             암호화된 키

수신자: RSA 개인키로 AES 키 복원 → 파일 복호화
```

알고리즘을 검토할 때는 AES-256-GCM과 RSA-OAEP(SHA-256)를 기준으로 삼았다. 인증 태그 검사에 실패하면 복호화 결과를 받아들이지 않도록 만드는 것도 중요하다.

## 구현하면서 체크할 것

| 항목 | 확인할 내용 |
| --- | --- |
| AES 키 | 파일 또는 작업마다 새로 생성하는지 |
| GCM nonce | 같은 키로 재사용하지 않는지 |
| RSA | RSA-OAEP 설정이 송수신 측에서 일치하는지 |
| 변조 검사 | 헤더·암호문·태그가 바뀌면 거부하는지 |
| 파일 처리 | 큰 파일과 폴더를 메모리 과다 사용 없이 처리하는지 |
| 복호화 도구 | 수신자 PC에서 같은 포맷을 읽을 수 있는지 |

암호화 도중 문제가 생기거나 인증 태그가 맞지 않으면 불완전한 평문이 남지 않게 처리해야 한다. 파일 크기, 작업 중단, 잘못된 개인키 같은 경우도 테스트 목록에 넣었다.

## ZIP과 자체 확장자를 혼동하지 않기

`.cpenc`나 `.cprsa`처럼 별도 파일 형식을 만들었다면 7-Zip에서 열리는 일반 ZIP 파일과 같다고 안내할 수 없다. 수신자가 내용을 복호화하려면 해당 형식에 맞는 도구가 필요하다. 암호화 성공 여부와 수신자 환경에서의 복호화 성공 여부도 따로 확인해야 한다.

## 아직 필요한 시험

- 작은 파일과 큰 파일의 암호화·복호화 왕복 확인
- 암호문을 일부 바꿨을 때 오류 처리
- 잘못된 개인키와 비밀번호 입력
- 중단된 작업의 임시 파일 정리
- 다른 Windows 환경에서 재현되는지

코드가 존재한다는 이유만으로 보안 검증까지 끝났다고 쓰지는 않을 생각이다. 결과를 남기게 되면 입력 조건과 오류 메시지도 함께 기록할 예정이다.
